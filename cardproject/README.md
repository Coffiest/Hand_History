# カード分割（アノテーション）

写真からトランプを検出し、1枚ずつ切り出すプログラムです。

```bash
python card_splitter_pro.py --input images/ --output output_results
```

引数と出力の形は `card_splitter_first.py` と同じなので、これまでの後工程はそのまま使えます。

```
output_results/<画像名>/
    <画像名>.jpg           元画像のコピー
    cards/card_1.jpg ...   1枚ずつ切り出したカード（256×392 JPEG）
    annotated/detected.jpg 検出枠を描いた画像
    masks/mask.jpg         前景マスク
```

追加オプション（すべて任意）:

| オプション | 内容 |
|---|---|
| `--debug` | 判断根拠になった中間画像を `debug/` に全部出す |
| `--json` | 四隅座標・スコア・使用エンジンを `results.json` に出す |
| `--engine` | `auto`（既定） / `classic` / `learned` |

---

## なぜ作り直したのか

旧版には調整では直せない構造的な問題がありました。

### `card_splitter_first.py`（エッジ方式）の限界

- **絵札の内枠を拾う**。白いカードが明るい木目の上にあると外周のエッジは弱く、
  絵札に印刷された内側の枠のほうが強い。エッジを追う限り強いほうが勝つ。
- **接触したカードを1枚と誤認する**。2枚を並べて置くと輪郭が融合し、その外接矩形は
  カード単位で 5.0 × 3.5、つまり縦横比 **1.428**。1枚のカードは **1.400**。
  その差わずか2%なので、**どんな縦横比フィルタでも原理的に区別できません**。

### `card_splitter_revenge.py`（白色抽出方式）の限界

光沢のハイライトも白、カード自身の地色も白。**同じ「白」なので分離できません。**

### 両者に共通する欠落

「カードは縦横比 2.5:3.5 の角丸長方形」「同じ写真の中のカードは全部同じ大きさ」という
**極めて強い事前知識を一切使っていなかった**こと。新版はここを軸に組み直しています。

## 仕組み

### 古典エンジン（学習不要）

1. **「白いもの」でも「エッジ」でもなく「テーブルでないもの」を探す。**
   画像の縁からテーブル色を取り、そこからの色差で分離します。明度より彩度を重く見るので、
   ハイライトで明るさが飛んでも下地の色は残り、光沢に強くなります。
2. **複数の二値化の結果を全部候補にする。** 単一のしきい値はどれかの照明条件で必ず崩れるので、
   5通り（テーブル色差 / 色クラスタ / Otsu / 低彩度 / Canny）を走らせ、どれか1つが当てれば拾えるようにします。
3. **カードらしさで採点する。** 縦横比 0.714 への近さ、矩形らしさ、四辺の下に実際のエッジがどれだけあるか。
4. **内枠を殺す。** カードの中にカードは入らないので、包含関係で判定します。
   ただし「入れ子の外側」が1枚のカードらしくない（外接矩形を埋めていない）場合は、逆に外側を捨てます。
   これで、しきい値がテーブルごと拾った巨大な塊が本物のカードを飲み込む事故を防ぎます。
5. **接触は「平らに直してから」割る。** 融合した塊を正面向きに変換すると、継ぎ目は必ず軸に平行な直線になります。
   そこで「全ての行で勾配が強い列」を探します。ピップや数字は一部の行にしか出ないので混同しません。
   （`revenge.py` は同じことを歪んだ元画像上でやろうとして失敗していました。）
6. **同じ写真のカードは同じ大きさ**という制約で、小さすぎる（内枠）・大きすぎる（未分割）を落とします。

### 学習エンジン（重なり対応）

古典手法は重なりに原理的に対応できません（隠れたカードには閉じた輪郭が存在しない）。
そこで小さなU-Net（約39万パラメータ）が画素ごとに
**背景 / カード内部 / カード境界** の3クラスを出します。

境界を明示的に予測するのが要点です。単なる「カードか否か」では接した2枚が1つの塊になりますが、
境界を彫り込むと**内部どうしが切り離される**ので、普通の連結成分で1枚ずつ取り出せます。

隠れて欠けたカードは、**縦横比が既知なので本来の長方形に復元**します。
このとき「どちら側が隠れているか」を、欠けた端の外側にカード画素があるかで判定して、
その方向にだけ伸ばします（左右対称に伸ばすと位置が半分ずれてしまうため）。
復元後は常に「1枚まるごとの形」になるので、既存のスートCNN・ランクSVMをそのまま使えます。

学習データは Drive の実写真363枚から**自動生成**します。1枚に1カードの写真から
「平らにしたカード」と「カードを消したテーブル」を取り出し、回転・遠近・重なり・光沢・影を付けて
組み直します。自分で配置しているので正解は画素単位で完全に正確で、手作業のラベル付けは不要です。

素材の取り出しは**写真1枚あたり0.5〜1秒**が目安です（800枚で10〜15分）。これより桁違いに遅い場合は、
背景プレートを元の写真解像度のまま補間していないか疑ってください。12MPの写真を
`cv2.inpaint` にそのまま渡すと**1枚50秒**かかります。プレートは合成シーン（256×192）の下地に
しかならないので、`PLATE_MAX_SIDE`（768px）まで縮小してから補間します。

学習は `research/notebooks/card_seg_synth_train.ipynb`（Colab、GPU無しでも可）。
出力された `card_seg_unet.pt` を `services/recognition/models/` に置くと有効になります。
**モデルが無い場合は自動的に古典エンジンで動く**ので、置かなくてもアプリは壊れません。

### `auto` は古典手法を優先します

学習モデルは**万能ではありません**。素材が足りないまま学習すると、重なりでは大きく勝つ一方で、
**離れて並んだカードという一番よくあるケースで古典手法に負けます**（実測で 90% → 61%）。
そのため `auto` は次の順で動きます。

1. まず古典手法で検出する
2. 結果が「きれい」なら（全部カードの比率で、大きさが揃っていて、スコアも十分）それを採用する
3. そうでないときだけ学習モデルに聞く

新しい重みを入れる前には、ノートブックが出す**学習に使っていない素材での比較表**を必ず見て、
「離れて並ぶ」が悪化していないことを確認してください。悪化していれば素材（写真の枚数・多様性）が
足りていないサインです。

なお `auto` が学習モデルまで行く場合は両方の時間がかかります（古典 約0.13〜0.39秒 ＋ 学習 約0.27秒）。
簡単なケースは古典だけで終わるので、通常は高速なままです。

## アプリとの関係

同じ検出コード（`services/recognition/app/recognition/card_splitter_v2.py`）を、
このツールと認識サーバーの両方が使います。ここで切り出したものとアプリが見るものが
食い違わないようにするためです。違いは出力サイズだけで、このツールは 256×392（旧版互換）、
サーバーは 600×900（ランクモデルの正規化サイズ）で切り出します。

なお、カメラをかざしている間の**ライブ検出（0.22秒ごと）は従来の軽い方式のまま**です。
あれは枚数と大まかな位置が分かれば十分なので、精度エンジンの時間をかける価値がありません。
精密な切り出しは撮影が確定した後に1回だけ走ります。
